# 病床機能報告ダッシュボード 設計書

## 1. データソース

厚生労働省「病床機能報告」オープンデータ
- URL: https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/open_data_00006.html
- 2014年度開始、年1回公開
- ZIPファイル（地域ブロック別に分割）で提供

### ファイル構成

| ファイル | 粒度 | 内容 |
|---|---|---|
| 施設票 | 医療機関単位 | 施設基本情報（所在地、構想区域、許可病床数等） |
| 診療所票 | 有床診療所単位 | 有床診療所固有の情報 |
| 様式1 病棟票 | 病棟単位 | 医療機能区分（高度急性期/急性期/回復期/慢性期）、6年後の予定機能、人員配置、設備 |
| 様式2 病棟票（月別） | 病棟×月 | 月別の入退棟患者数、在棟日数等 |
| 様式2 病棟票（年間合計） | 病棟×年 | 年間の診療実績（手術件数、救急車搬送、分娩件数等） |

### 主要指標

- 医療機能区分（現在 / 6年後の予定）
- 許可病床数・稼働病床数
- 新規入棟患者数（予定入院 / 緊急入院）
- 退棟患者数（在宅復帰 / 他院転院等）
- 病床利用率（入院患者延べ数から算出）
- 平均在棟日数
- 全身麻酔手術件数
- 救急車搬送受入件数
- 分娩件数
- t-PA件数、人工心肺手術件数
- 化学療法件数、放射線治療件数
- リハビリテーション提供状況
- 人工透析件数
- 算定入院料の種類
- 医師・看護師配置数

### データ規模

- 全国約8,000病院 + 約7,000有床診療所
- 5年分蓄積
- 施設票: ~15,000行/年、病棟票: ~50,000行/年

## 2. ターゲットユーザー

| ユーザー | 利用シーン |
|---|---|
| 自治体の医療政策担当者 | 地域医療構想の進捗確認、必要病床数と現状のギャップ分析 |
| 病院の経営企画部門 | 自院のポジショニング確認、構想区域内の競合分析 |
| コンサルティング会社 | 病院再編・統合の提案資料、地域分析 |
| 研究者・メディア | 医療提供体制の地域間格差分析 |

## 3. ダッシュボード構成（5ページ）

### Page 1: 全国俯瞰マップ (`/`)

**仮説**: 病床の機能転換は地域医療構想通りに進んでいるのか？

**コンポーネント**:
- 日本地図（構想区域別ヒートマップ）: 339区域を色分け
  - 赤: 高度急性期/急性期が過剰
  - 黄: 回復期が不足
  - 緑: バランス良好
- サマリーカード: 全国の総病床数、機能別内訳（円グラフ）、必要病床数との乖離率
- 4機能別の積み上げ棒グラフ（報告値 vs 必要病床数）
- KPIカード: 総病床数 / 病床利用率 / 急性期過剰率

**フィルタ**: 都道府県、人口規模、年度スライダー

### Page 2: 構想区域別詳細分析 (`/area`)

**仮説**: 同じ構想区域内でも病院ごとに機能の偏りがあるのでは？

**コンポーネント**:
- 構想区域セレクタ
- 病院別 機能別病床構成の横棒グラフ
- 散布図: 横軸=病床数、縦軸=病床利用率、バブルサイズ=救急車搬送件数
- 必要病床数とのギャップ分析テーブル

### Page 3: 診療実績ランキング (`/ranking`)

**仮説**: 手術件数や救急搬送件数の集中度で地域の中核病院が浮かび上がる

**コンポーネント**:
- 指標セレクタ: 全身麻酔手術 / 救急車搬送 / 分娩 / 化学療法 / 放射線治療 / t-PA等
- 上位20病院の横棒チャート + テーブル
- 構想区域内シェアのツリーマップ
- 経年推移の折れ線グラフ（選択病院）

**フィルタ**: 全国 or 構想区域

### Page 4: 経年変化トレンド (`/trend`)

**仮説**: 病床機能の転換は年々進んでいるのか、停滞しているのか？

**コンポーネント**:
- 4機能別 病床数の積み上げ面グラフ（5年推移）
- 機能転換率のKPIゲージ
- 予定 vs 実績の比較棒グラフ
- 都道府県別の回復期充足率ランキング推移

**フィルタ**: 全国 / 都道府県 / 構想区域

### Page 5: 病院個別カルテ (`/hospital`)

**仮説**: 個々の病院の立ち位置を全国平均・区域平均との比較で診断できる

**コンポーネント**:
- 病院名検索
- レーダーチャート: 病床利用率、救急搬送件数、手術件数、平均在棟日数、看護師配置密度（vs 全国平均・区域平均）
- 5年間の病床数・機能区分の推移
- 病棟別詳細テーブル

## 4. 技術構成

| 項目 | 選定 | 理由 |
|---|---|---|
| フレームワーク | Next.js 14 (App Router) | SSG/ISR対応、Vercelデプロイ |
| チャート | Recharts | React対応、宣言的API |
| 地図 | Leaflet (react-leaflet) | 無料、GeoJSON対応 |
| スタイル | Tailwind CSS | ユーティリティファースト |
| データ | 静的JSON | ビルド時生成、CDN配信 |
| 前処理 | Python (pandas) | CSV処理に最適 |
| デプロイ | Vercel | Next.jsとの親和性 |

### データパイプライン

```
厚労省ZIP → data/raw/ (CSV) → scripts/preprocess.py → public/data/ (JSON) → Next.js
```

### JSON出力ファイル設計

```
public/data/
├── summary/
│   ├── national.json          # 全国集計（年度別、機能別病床数）
│   └── prefectures.json       # 都道府県別集計
├── areas/
│   ├── {area_code}.json       # 構想区域別の病院一覧と集計
│   └── index.json             # 構想区域マスタ（コード、名称、都道府県）
├── hospitals/
│   ├── {hospital_code}.json   # 病院個別データ（5年分）
│   └── index.json             # 病院マスタ（検索用）
├── ranking/
│   └── {year}.json            # 年度別ランキングデータ
└── geo/
    └── areas.geojson          # 構想区域のGeoJSONポリゴン
```

## 6. 差別化ポイント

- **5年分の経年比較**: 既存ツールは単年度のみが多い
- **全国横断・無料**: オープンデータのみ使用
- **インタラクティブ**: PDF/Excelの静的資料ではなくWebダッシュボード
- **予定 vs 実績の乖離分析**: 6年後の予定機能と実際の変化を追跡
- **構想区域フォーカス**: 地域医療構想の単位に合わせた分析
